# M3 exploratory expression measurements

Measured 31 October 2026 on a shared x86-64 cloud worker (3 visible CPUs,
Intel Xeon Platinum 8573C, JDK 25.0.5). The machine was not designated as a
reference environment; other Gradle work overlapped the first run. These results
are diagnostic and do not complete the M2 or M3 performance gates.

The first run used source commit `28a4af8`, JMH average time, 65,536 float64
values, three forks, two 1-second warmups and three 1-second measurements. Raw
results are in [before-copy-optimization.json](m3-exploratory/before-copy-optimization.json).
Block out was 7,881 ± 1,373 µs/op, eager out 249 ± 35 µs/op, and generated out
829 ± 675 µs/op. Errors are JMH's reported score errors. The generated result
does not demonstrate the proposed speedup, and the block path was substantially
slower. Results include allocation and traversal differences documented by the
benchmark source.

Inspection found contiguous blocks were copied one element at a time. The second
run includes the accompanying contiguous bulk-copy change and uses one fork with
the same warmup and measurement settings. Its raw data is in
[after-copy-optimization.json](m3-exploratory/after-copy-optimization.json).
It reported block out 330 µs/op, eager out 240 µs/op, generated out 469 µs/op.
A single fork and changed system load make this an exploratory check, not a
controlled before/after claim. Results still show no verified generated speedup.

Designate a stable reference machine, repeat the agreed three-fork campaign at
all sizes and layouts, include SIMD-enabled eager runs and cold/compile costs,
and review the automatic threshold. Small-array budgets, cross-platform and
full allocation measurements remain open. Do not release on the basis of these
shared-machine measurements.

A further single-fork exploratory run inlined the generated expression body into
the generated traversal loop, avoiding the per-element input array and interface
call. Raw results: [inline-generated-loop.json](m3-exploratory/inline-generated-loop.json).
It reported block out 325 µs/op, eager out 255 µs/op, and generated out 344 µs/op
at 65,536 elements. This is still shared hardware and is not release evidence;
the target remains unverified and the generated path did not show a speedup in
this sample.

Local correctness checks during this work included the root build, a required
SIMD build with the OpenBLAS linalg backend check, the JIT property suite, and
classpath/module-path staged consumers. These runs occurred against the working
tree, not a release commit; the final candidate and its remote checks must be
verified separately.
